## 快速开始

### 1. 零硬件跑通链路（不需要摄像头、不需要 VPN、不花钱）

```powershell
cd phase1
python -m civility.cli check     # 体检
python -m civility.cli all       # 抽帧 → 推理(mock) → 聚合 → 评测
```

看 `runs/default/report.md`。这一步验证的是**管道**，不是识别效果。

### 1.5 不接任何摄像头，验"摄像头监测"（推荐先做这一步）

本机网络被隔离、装不了现成的 RTSP 服务器，所以仓库里自带了一个：

```powershell
cd phase1
# 两条演示流：demo_cam=真实工地画面（吸烟）；demo_litter=合成的丢垃圾动画
python tools/make_demo_stream.py                                   # 生成（只需一次）
python tools/mini_rtsp_h264.py --h264 runs/demo_cam.h264 --port 8554 --fps 20
python -m webui.server                                            # 另开一个窗口起网页
python tools/test_monitor_rtsp.py --seconds 32                     # 自动跑完并逐项断言
```

网页「① 摄像头监测」里源填 `rtsp://127.0.0.1:8554/live`，
勾上「演示模式」就能在**不连集群**的情况下看到完整的持续监测：
左上角「实时画面」以约 3 张/秒流畅刷新、每 6 秒产出一个窗口、
AI 逐人说明在做什么、告警区实时刷新。

> ⚠️ **两条演示流的用途完全不同**（实测对比见 `WEBUI-可视化界面.md` §6.5）：
> · `demo_cam.h264`（**真实**工地画面）→ 真模型能识别，3/3 命中「吸烟 95%」
> · `demo_litter.h264`（**合成**火柴人动画）→ 真模型 0 命中，它不会把动画里的
>   方块移动判成"乱扔垃圾"。它只适合验链路，不要用它判断识别效果。

> 这条路径走的是**和真实摄像头完全一样**的 OpenCV + FFmpeg RTSP 客户端代码，
> 所以它验的是真链路，不是替身。
> 该测试实测 9 项断言全过，细节与期间挖出的 5 个 bug 见 `WEBUI-可视化界面.md` §6.4。

### 2. 用可视化网页（需要 VPN）

```powershell
$env:VLM_SSH_PASSWORD = '<集群密码>'      # 或先配免密

python -m civility.cli cluster-prepare     # 打包（只需一次）
python -m civility.cli cluster-upload      # 上传到 A800（只需一次）

python -m webui.server                     # 启动网页
```

浏览器打开 **http://127.0.0.1:8848** → 点「启动服务」→ 等 1-3 分钟 →
①页填源跑实时监测，或 ②页拖视频进去看结果。

> ⚠️ 用完记得点「停止并释放节点」，否则一直占着一张 A800（约 4 元/卡时）。

### 3. 不想被扣钱：先看这一节

**网页有成本守卫，但你也应该知道怎么手动查。**

```powershell
$env:VLM_SSH_PASSWORD = '<集群密码>'
python tools/cluster_cost.py            # 现在有没有作业在跑、已花多少
python tools/cluster_cost.py --stop     # 一键停掉本项目所有作业
python tools/cluster_usage.py --days 14 # 近两周花了多少（对账）
```

网页侧的三道保险（详见 `WEBUI-可视化界面.md` §5②）：

| 机制 | 什么时候触发 |
|---|---|
| 空闲自动释放 | 页面关掉 / 切后台 / 开着但 15 分钟没碰鼠标键盘 |
| 最长运行上限 | 服务连续跑满 3 小时（正在分析画面时不会被硬切） |
| 孤儿检查 | 每次启动网页时扫一遍集群，发现没人管的作业就挂红色横幅 + 一键停 |

> 为什么必须做这些：实测 14 天里有一个服务作业跑满 12 小时被 TIMEOUT，
> 单它约 **12 GPU·小时 ≈ 48 元**，占那段时间全部花费的 **85%** ——
> 起因就是网页重启后作业号丢失，集群上的作业变成了没人管的"孤儿"。

## 模型能力：实测能做与不能做

用**画面里有明确内容**的视频验证过（`tools/verify_visible.py`，4/4 通过）：

| 能做 | 不能做 |
|---|---|
| 读中文标牌（「停车场 3 号门」完全正确） | 描述运动方向/速度（会把"明显在走的人"说成"静止"） |
| 认出"把物体丢到地上"（含跨帧变化） | — |
| 人站在垃圾桶旁但没丢东西时**不误报** | — |
| 空场景不无中生有 | — |

> **实用结论**：判断行为看 `observable`（模型给的判定依据），
> 不要看 `scene` 里的运动描述。
> ⚠️ 但仍**没有任何真实监控画面上的准确率数据** —— 见 `WEBUI-可视化界面.md` §6.1、§7。

## 三条最重要的实测结论

1. **集群装不了 vLLM**（glibc 2.28 < `manylinux_2_31`），只能走纯 transformers。
   代价是没有 continuous batching —— **单窗口延迟 5.5 秒就是硬下限**，
   这决定了"实时"能到什么程度。详见 `WEBUI-可视化界面.md` §3。

2. **坏节点列表比旧文档多三个**。逐个实测 19 个 A800 节点后确认，
   驱动 550.54.14（CUDA 不可用）的是 `gpu8007 / gpu8011 / gpu8012 / gpu8015`，
   而旧文档只列了 `gpu8002/8003/8012`。硬编码过期列表会让作业随机失败。

3. **网页必须放本机**。计算节点无公网入口、登录节点没装 web 框架且禁止长期占用
   —— 所以是「本机网页 + SSH 两级隧道 + 计算节点常驻模型」的架构，
   而不是"网页部署在服务器上"。
